## 2026-08-31: explicit active presence identity

The reconstruction notes above describe the original scaffold state and are retained as history;
the source is now present and builds. `PresenceState` now owns an explicit `activeName`, sets it before
posting `PresenceStartEvent`, returns that exact value for the whole presence window, and clears it
after `PresenceEndEvent` or a full reset. This removes the implicit dependency on re-reading
`FakeIdentity` and gives sibling mods one authoritative sender for a join/chat/leave sequence.

Clean NeoForge 1.21.1 compilation passed. Equivalent Forge 1.19.2 and 1.20.1 multi-project builds
passed, and the deployed JARs contain the `activeName` field. Runtime event ordering remains to be
confirmed in Minecraft.

## 2026-09-05: 1.0.1 interval hardening

Presence-duration selection now uses long-width range arithmetic, preventing a valid extreme config
from overflowing the old inclusive `nextInt` bound. The explicit active identity remains unchanged.
Clean NeoForge 1.21.1 and complete Forge 1.19.2/1.20.1 builds passed; in-game sequencing is still
pending.

## 2026-09-07: 1.0.2 dedicated-server presence bridge

Haunted Core now has optional client-to-server networking for the currently active fake identity.
Server state is keyed by the real player's UUID rather than kept globally. NeoForge uses an optional
payload registrar and Forge checks that the remote channel is present before sending, preserving
compatibility when the server does not have Haunted Core. Logout cleanup lives in Haunted Core itself,
so state is cleared even if Haunted Chat is absent. `EventCoordinator` also has server-game-time quiet
period methods, keeping client and dedicated-server clocks separate.

logout handler and match their build outputs: NeoForge
